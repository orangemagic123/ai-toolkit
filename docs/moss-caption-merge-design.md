# MOSS JSON + 태그 TXT 일괄 결합 설계안

상태: 별도 Windows GUI 구현 완료. 소스는 `tools/moss_json_merger/`, 실행 파일은 `output/moss_json_merger/MOSS_JSON_Merger.exe`에 있다. 사용 방법과 실제 지원 범위는 소스 폴더의 README.md를 기준으로 한다.

## 목적

이미지별 MOSS JSON의 `caption.short`, `caption.medium`, `caption.long`, `watermark`, `borders`와 기타 필드를 보존하면서, 대응하는 태그 TXT에서 `tags`와 `keep_tags`를 가져온다. 결과는 현재 ai-toolkit의 `caption_format: moss_json`에서 읽을 수 있어야 한다.

프로그램 형태는 사용자가 선택한 별도 Windows GUI로 확정한다. `001.json`과 `001.txt`처럼 이름이 같은 파일을 연결한다. GUI와 결합 엔진은 분리하고 ai-toolkit 웹 UI나 llama 서버에 연결하지 않는다. 서로 다른 입력 폴더도 지정할 수 있도록 한다.

## 입력과 파일 매칭

- JSON 루트 폴더와 태그 TXT 루트 폴더를 각각 선택한다. 같은 폴더도 허용한다.
- 하위 폴더 포함 여부를 설정한다.
- 기본 매칭 키는 각 루트에서의 상대 경로에서 마지막 확장자를 제거한 값이다.
- 예: `json/character_a/001.json` ↔ `tags/character_a/001.txt`.
- 서로 다른 하위 폴더에 있는 같은 이름의 파일을 파일명만으로 임의 연결하지 않는다.
- 이름이 다르면 접미사 제거 등 명시적인 변환 규칙을 추가할 수 있게 하되, 1차 구현에서는 같은 이름과 같은 상대 경로를 기본으로 한다.
- 여러 후보로 해석되는 경로는 충돌로 표시하고 자동 결합에서 제외한다.
- 출력·백업·실행 보고서 폴더는 재귀 탐색에서 제외한다.
- 앞서 만든 ComfyUI 워크플로우는 자연어 TXT도 출력한다. 결합 대상 TXT에는 태그 파일을 명시적으로 지정해야 하며, 자연어 파일을 태그 입력으로 자동 추정하지 않는다.

## TXT 해석과 보호 태그

예시 입력:

```text
1girl, char, artist ||| apple, solo, red eyes
```

해석 결과:

```json
{
  "keep_tags": ["1girl", "char", "artist"],
  "tags": ["apple", "solo", "red eyes"]
}
```

- 기본 태그 구분은 쉼표다. 공백을 다듬고 빈 항목을 제외한다.
- 보호 구분자는 실제 TXT 예시에 맞춰 `|||`를 기본값으로 한다. 사용자가 바꿀 수 있게 한다. 첫 번째 구분자 앞의 태그를 순서대로 `keep_tags`에 넣는다. 구분자 문자는 결과 태그에 넣지 않는다.
- 구분자가 없으면 TXT의 태그는 모두 일반 태그로 분류한다. 보호 태그를 추측하지 않는다.
- 공통 보호 태그를 별도 입력하는 기능을 제공한다. 이를 모든 처리 대상의 `keep_tags`에 추가한다.
- 중복은 대소문자와 표기를 유지하는 정확한 문자열 비교로 제거한다. 처음 등장한 순서를 보존한다.
- `keep_tags`에도 있는 태그는 일반 `tags`에서 제외한다.
- 대소문자, 언더스코어, 괄호, 가중치 표기 등을 임의 변환하지 않는다.
- 여러 줄 태그의 줄바꿈 처리와 secondary separator 그룹 처리는 실제 TXT 예시를 확인한 후 확정한다. 줄마다 서로 다른 캡션인 파일을 임의로 하나로 합치지 않는다.
- 기본 인코딩은 UTF-8/BOM을 허용한다. 해석 실패는 오류로 표시하고 필요하면 사용자가 입력 인코딩을 지정한다.

## 기존 tags / keep_tags가 있는 JSON

세 가지 정책을 제공한다.

| 정책 | 동작 |
| --- | --- |
| 합치기 — 기본 제안 | 기존 태그를 보존하고 TXT의 새 태그를 추가 |
| TXT 기준 교체 | 두 태그 필드를 현재 TXT와 공통 보호 태그 기준으로 다시 생성 |
| 빈 필드만 채우기 | 기존 값이 비어 있는 필드에만 가져온 값을 적용 |

합치기의 순서는 다음과 같이 명시한다.

1. `keep_tags`: 기존 보호 태그 → 공통 보호 태그 → TXT 보호 태그.
2. `tags`: 기존 일반 태그 → TXT 일반 태그.
3. 각 목록에서 중복을 제거하고, 최종 보호 태그를 일반 태그에서 제외한다.

각 목록에 먼저 있던 항목의 순서를 보존한다. 같은 파일을 같은 설정으로 다시 처리하면 중복이 늘어나지 않으며, 결과가 같으면 저장하지 않는다. TXT에서 삭제한 태그까지 결과에서 제거하려면 교체 정책을 사용한다.

## 검증과 미리보기

저장하기 전에 전체 매칭과 변환 결과를 만든다.

미리보기 표:

| JSON 상대 경로 | TXT 상대 경로 | 기존/결과 keep 수 | 기존/결과 일반 태그 수 | 상태 |
| --- | --- | --- | --- | --- |
| character_a/001.json | character_a/001.txt | 0 → 3 | 0 → 3 | 변경 예정 |
| character_a/002.json | 없음 | — | — | TXT 없음 |

- 항목 선택 시 원래 JSON과 변경될 두 태그 필드를 비교해서 보여 준다.
- 변경 예정, 변경 없음, 파일 누락, JSON 오류, TXT 해석 오류, 매칭 충돌로 구분한다.
- JSON의 세 자연어 필드가 유효한 비어 있지 않은 문자열인지 검증한다.
- `tags`와 `keep_tags`의 기존 값이 잘못된 형식이면 자동으로 버리지 않고 오류로 표시한다.
- 대응 JSON이 없는 TXT도 별도 목록으로 보여 준다. 자연어 캡션이 없는 JSON을 임의로 생성하지 않는다.
- 사용자가 정상 항목 중 적용할 대상을 선택할 수 있게 한다. 일부 파일 오류로 정상 파일의 미리보기까지 중단하지 않는다.

## 저장

- 기본 제안은 원래 JSON 위치에 갱신하고, 바뀌는 파일의 원본을 실행별 백업 폴더에 먼저 저장하는 방식이다. 학습할 이미지 옆에 결합된 JSON이 있어야 하기 때문이다.
- 원본을 수정하지 않고 별도 폴더에 JSON만 출력하는 선택지도 제공한다. 이 경우 학습 시 사용할 이미지와 JSON의 배치는 사용자가 정해야 한다.
- 저장 직전에 JSON과 TXT가 미리보기 이후 바뀌지 않았는지 확인한다. 바뀌었으면 해당 항목을 건너뛰고 재검사를 요청한다.
- 임시 파일을 같은 폴더에 완성한 뒤 최종 파일로 교체해, 중간에 끊긴 JSON이 남지 않도록 한다.
- 취소하면 현재 파일 처리를 마친 뒤 중단한다. 완료한 파일과 남은 파일을 구분한다.
- 자연어와 기존 메타데이터의 JSON 값은 그대로 보존한다. JSON 들여쓰기나 Unicode 이스케이프 표현은 바뀔 수 있다.
- 결과는 UTF-8 JSON으로 저장하고, 상대 경로·결과 상태·오류 이유·백업 위치가 있는 실행 보고서를 남긴다.

## 화면 구성 제안

1. 입력: JSON 폴더, 태그 TXT 폴더, 하위 폴더 포함.
2. 처리 규칙: 보호 구분자, 공통 보호 태그, 기존 태그 처리 정책.
3. 저장: 원본 갱신/별도 폴더와 백업 위치.
4. `검사 / 미리보기`: 매칭 표와 항목별 변경 상세.
5. `선택한 항목 결합`: 진행률, 완료/변경 없음/실패 개수, 취소.

학습용 short/medium/long 선택 비율은 이 도구에 넣지 않는다. 세 캡션을 모두 보관하고 ai-toolkit 학습 설정에서 비율을 선택한다.

## 내부 구성과 검증 기준

결합 엔진을 GUI와 분리해 파일 매칭, TXT 파싱, 태그 결합, 실행 계획 생성, 저장 기능을 각각 검증할 수 있게 한다. 이미지 모델이나 llama 서버 호출은 사용하지 않는다.

검증할 실제 동작:

- 하위 폴더에 같은 파일명이 있어도 올바른 쌍만 매칭.
- 보호 태그 순서 유지, 일반 태그와의 중복 제거.
- 구분자가 없는 TXT, 빈 TXT, BOM, Unicode, 잘못된 JSON 처리.
- 기존 태그가 있는 JSON에서 각 정책의 정확한 결과.
- 같은 작업을 반복해도 결과가 동일함.
- 자연어 문자열과 기타 JSON 필드가 결합 전후 동일함.
- 미리보기 후 원본이 바뀐 경우 변경을 덮어쓰지 않음.
- 저장 실패와 취소 상황에서 백업과 보고서가 일치함.

## 확정 사항과 남은 기본값

- 확정: 별도 Windows GUI.
- 확정: `001.json` ↔ `001.txt`처럼 같은 이름으로 매칭.
- 확정: `1girl, char, artist ||| apple, solo, red eyes`에서 구분자 앞은 보호 태그, 뒤는 일반 태그로 변환.
- 제안 기본값: 원본 JSON 갱신 + 실행별 원본 백업, 기존 태그와 합치기, UTF-8/BOM 허용, 공통 보호 태그는 비워 둠.
- 실제로 여러 줄 태그나 secondary separator 그룹이 있으면 파일 예시를 확인해 추가 지원 범위를 정한다.
